PI Copilot

Module PICopilot, version 0.2.2.0 (2026-10-13). Process > <Etc> > PICopilot opens the panel. This document is installed with the module (doc/tools/PICopilot/).

PI Copilot is a chat panel for PixInsight. You talk to Claude, an AI model made by Anthropic, using your own Anthropic API key. It can see the active image (a small preview, its statistics and keywords) and, depending on the mode you choose, run PixInsight processes on your images, start installed PixInsight scripts that you confirm, and record how each image was processed.

Modes

  • Copilot: applies processes when you ask. Every change is recorded in the image's History, so Undo works.
  • Guided: shows each process and its parameters and runs it only if you press Yes (the default is No).
  • Advisor: read-only. It looks and advises; it never changes an image and never runs a script.

Some processes always ask first, in every mode (they write files, close windows or change PixInsight settings), and some are never run by PI Copilot (for example Preferences, ProcessContainer, Script, the INDIGO device processes). The full list is in the module's README.

Data sent to Anthropic, and your consent

PI Copilot sends nothing anywhere until you agree. Before your first message it shows a dialog that names Anthropic, lists what can be sent and links to Anthropic's privacy policy (https://www.anthropic.com/legal/privacy). If you do not agree, nothing is sent. Your agreement is stored in PixInsight's settings; you can withdraw it at any time in the settings dialog (the ⚙ button: uncheck Send data to Anthropic and press OK). The check is made where every request is built, so neither chat messages nor journey write-ups can be sent without it.

What can be sent

  • The text you type and the conversation so far.
  • With Include view on: an auto-stretched JPEG preview of the active image (at most 1024 pixels on its long side), its size, view id, per-channel statistics (median, deviation, mean, minimum, maximum), its file name (never the folder), and up to 60 of its FITS keywords. Keywords that name a place or a person are never sent: SITELAT, SITELONG, SITEELEV, OBSGEO-B, OBSGEO-L, OBSGEO-H, LAT-OBS, LONG-OBS, ALT-OBS, OBSERVER, and in any spelling (also HIERARCH and long names) every keyword whose name contains SITE, OBSGEO, GEOLAT/GEOLON/GEOELEV, LATITUD, LONGITUD, GPS, OBSERVER, OBSERVAT, LOCATION, AUTHOR or a LAT/LON/ELEV/ALT part. COMMENT and HISTORY keywords are never sent. Every folder path inside a keyword value (also Windows, network-share, ~/ and file:// paths, and relative paths) is reduced to its file name; a folder name, or a path cut short, becomes [path].
  • Results of what PI Copilot looks up or does for you: other images' previews and statistics, process descriptions and parameters, an image's processing history, your workspace process icons, the list of installed scripts, and the console output of a script you let it run. File names only, never folders.
  • Image journey data: recorded steps, their statistics, acquisition facts (target, filter, camera, gain, exposure, number of subframes, dates) and file names: to the chat model when you ask about a journey, and to Claude Haiku when you keep a journey, to write its journey.md. No image is sent for the write-up.

Never sent: your files themselves, full-resolution image data, folder paths, location or observer keywords. Your API key is sent only to Anthropic, as the credential of each request.

https://api.anthropic.com/v1/messages (same) Only when you keep a journey (★ Keep journey, or by asking in the chat), to write journey.md. Your API key, model claude-haiku-4-5, fixed instructions, and a condensed recipe of the journey (steps, statistics, acquisition facts, file names). No image.

PI Copilot makes no other network connection. Each request has an overall limit of 600 s, and a reply stream that is silent for 120 s is stopped.

Scripts: run_script

PI Copilot never runs code written by the model. (Versions up to 0.2.1.1 had a tool, run_pjsr, that could run a script the model wrote after you approved it; 0.2.2.0 removed it completely.) Instead, the model can ask PixInsight to run a script that is already installed, choosing it by an id from a list PI Copilot builds. It never supplies a file path or any code. A script can be on that list only if all of these hold:

  1. Its real location, with symbolic links resolved, is inside PixInsight's script directory (<PixInsight>/src/scripts), where the PixInsight distribution and update packages install scripts. Links that lead elsewhere, paths with .. and unusual characters are refused.
  2. It is a main script (it has a #feature-id) and is not one of PixInsight's developer tools (Script > Development: code signing, signing keys, CPD submission, documentation compiler).
  3. It is signed: a .xsgn signature file is next to it, PixInsight's own signature check reports it valid for the file as it is now (the signature covers the script and every file it includes, so any change to the code invalidates it), and the signer is in PixInsight's database of certified developers. This holds even if you allowed unsigned scripts in PixInsight's security preferences: PI Copilot never runs an unsigned script.

PixInsight does not record which update package installed which file, so a script copied into the script directory by hand is refused unless it carries a valid signature of a certified developer.

Before suggesting a script, the model can read its description (describe_script): its menu entry, version, description, whether it works on a view or globally, which parameters it reads (with their types and defaults) and whether it opens a dialog. This is read from the script's source text; nothing is executed to find it out.

Every run asks you first, in Copilot and Guided mode alike (never available in Advisor). The dialog shows the script's menu entry, file, signing developer, the image it runs on (or "globally") and the arguments; the default answer is No. PixInsight then loads, checks and runs the file itself, exactly as from a process icon. Arguments must be parameters the script reads, with the right types, and may contain only letters, digits, spaces and . _ - + : / , = @ # ( ) [ ] { } ! ~ ^ ' & % ; (PixInsight passes them on a command line; each of these is tested to arrive unchanged, so file paths with spaces work). What the script tools tell the model never contains a folder: script files are named relative to the script directory, and a script's console output has its paths reduced to file names. A script runs with full access to PixInsight and your files, may open its own dialogs, and cannot be stopped by PI Copilot once it starts. In an image journey, the steps a script makes are recorded as PI Copilot's and are never re-run by a replay.

Image journeys

From the moment a stacked master is opened, PI Copilot records each step of its processing locally (the library above), whether you or PI Copilot made it. You can keep your best result as a process icon set, a recipe and a write-up, compare new data with it, and ask PI Copilot to replay it on a new master. Recording can be turned off in ⚙.

Developer self-test

The module contains a self-test that runs only when the environment variable PICOPILOT_SELFTEST_OUT is set by its test harness (in an isolated PixInsight instance slot). In a normal installation that variable is not set, and running the PICopilot process only points you to the panel: no settings are written, nothing is sent, no file is created.
