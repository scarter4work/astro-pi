SERViewer

Module Planetary. Process > Planetary > SERViewer. This document is installed with the module (doc/tools/SERViewer/).

SERViewer opens SER video files, the format planetary (lucky-imaging) capture programs such as FireCapture and SharpCap write, and uncompressed 8-bit greyscale or raw Bayer AVI files such as ASIAIR captures. An AVI can be saved as a SER file. Executing the process globally opens one frame of the video as an ordinary PixInsight image window, so every PixInsight tool can be used on it.

The interface

  • Open... (dialog caption “Open planetary video”) chooses a .ser or .avi file; the file filters are Planetary video (*.ser *.avi), SER video and AVI video. Its first frame is drawn in the preview. Opening a new file sets the Bayer pattern back to Auto.
  • Bayer pattern (AVI only; disabled for a SER, which states its own layout): Auto, None (mono), RGGB, GRBG, GBRG or BGGR. See AVI files. Changing it reopens the AVI on the same frame. This is the bayerPattern parameter.
  • Save pattern... (only for an AVI with no sidecar; enabled once you choose RGGB, GRBG, GBRG or BGGR with Debayer checked) remembers the chosen pattern in a sidecar next to the video. See Remembering a chosen pattern.
  • Save as SER... (AVI only) writes the whole video as a SER file. See Save as SER.
  • Debayer: for Bayer files, show and open frames as RGB (checked) or as the raw CFA mosaic (unchecked). This is the debayer parameter.
  • The preview shows the selected frame scaled to fit, keeping its proportions, on a black background. Its brightness is stretched linearly from 0 to the frame's brightest sample, so a dim planet still fills the display range; an all-zero frame shows black. The stretch is for viewing only: the image that Apply Global opens holds the unstretched samples.
  • Frame: the slider and the number box select the frame (0 to the frame count minus one). They are disabled until a file is loaded.
  • The info block lists the file name, width × height, frame count, colour layout, bit depth (followed by the depth the samples are normalised to, when that differs), the byte order used for 16-bit samples, the UTC time of the first frame (from the timestamp trailer, or none), the header's UTC start time, and any warnings from the reader, plus a warning for the frame shown when its samples exceed the normalisation range. If a file cannot be read, the preview is cleared and the reason is shown here (and in a message box when you chose the file).
  • Apply Global (the round button) opens the selected frame as an image window.

Dragging the interface's instance triangle onto the workspace saves a process icon with the file, frame and debayer and Bayer pattern settings; opening that icon restores them. The file stays open only while the interface shows it.

Parameters

ParameterTypeDefaultMeaning
filePathString(empty)Absolute path of the .ser or .avi file (the format is recognised from the file's content). The process cannot run while it is empty.
frameIndexInt320Frame to open, counting from 0.
debayerBooleantrueBayer (colour-sensor) files only: open as debayered RGB (bilinear interpolation) when true, or as the raw one-channel CFA mosaic when false.
bayerPatternEnumAutoAVI only, ignored for SER: Auto, None (mono), RGGB, GRBG, GBRG or BGGR.
saveSerPathString(empty)When not empty, executing the process converts the AVI in filePath to a SER file at this path instead of opening a frame. It converts AVI input only, and does not replace an existing file.

The image it opens

  • 32-bit floating point. Samples are divided by 2depth − 1, so the camera's full range maps to [0,1]. A file whose first frame holds values above its declared bit depth (the header understates it) is normalised by the full range of its sample size instead, 28 − 1 or 216 − 1, so the values stay within [0,1]; a warning says so. If a later frame of a file normalised by its declared depth still exceeds it, that frame opens with values above 1.0 and a warning (Process Console, HISTORY, info block) names the frame.
  • Identifier: the file name with every character other than letters, digits and underscores replaced by an underscore (an underscore is put in front if it starts with a digit), followed by _f and the frame number, for example Saturn_f0. PixInsight adds a suffix if that identifier is already in use.
  • FITS keywords:
    • DATE-OBS: the frame's own UTC timestamp when the file has a timestamp trailer, otherwise the file's UTC start time; left out when neither is valid. AVI frames never get a DATE-OBS: an AVI carries no timestamps, and the clock in an ASIAIR file name is not trustworthy as UTC.
    • INSTRUME, TELESCOP, OBSERVER: the camera, telescope and observer text from the file header, left out when empty. For an AVI, INSTRUME is the camera named in the ASIAIR sidecar.
    • BAYERPAT (RGGB, GRBG, GBRG or BGGR): when a Bayer file is opened with debayer false.
    • HISTORY: the source file name and frame number, plus one SERViewer warning: line for each problem the reader recovered from and for a frame whose samples exceed the normalisation range. Text longer than one FITS card (72 characters) continues on the next HISTORY card.
    Keyword text is plain ASCII: any other character from the file header or the file name is shown as ?.

AVI files

SERViewer reads uncompressed 8-bit AVI files: either palettised video whose palette is the identity grey ramp (entry i is (i, i, i)), which is what ASIAIR writes, or raw Y800/GREY/Y8 greyscale video (rows padded to a multiple of 4 bytes or not; ffmpeg writes them unpadded). Classic AVI files and OpenDML files (larger than 1 GB) both open, and a video is read one frame at a time, never loaded whole. Frames are normalised by 255.

These are refused with a message saying so: compressed video (the codec is named), video that is not 8 bits per pixel (for example 16-bit or 24-bit), a palette that is not the identity grey ramp, and files with palette-change chunks. Zero-length (dropped) frames are skipped and counted in a warning. At the first bad index entry (one that points outside the file, at the wrong size, or back over an earlier frame) that frame and all later ones are dropped, with a warning naming the entry. Only the first, middle and last frames' chunk headers are read when the file opens, so a bad entry between those checks shows as an error when that frame is displayed.

Bayer pattern and the ASIAIR sidecar

ASIAIR writes a text file next to each capture, <name>.avi.txt. The pattern choice works as follows.

  • Auto uses the sidecar's Bayer value (RG, GR, GB or BG for RGGB, GRBG, GBRG or BGGR). The sidecar's camera name becomes INSTRUME. With no sidecar, a sidecar that could not be read, something at the sidecar path that is not a file, or no Bayer value in it, the raw CFA frame opens as mono and a warning says which of these it was and asks you to choose the pattern.
  • Flip = Vert. When the sidecar says Flip = Vert, Auto uses the pattern rotated by 180° (RGGB becomes BGGR, GRBG becomes GBRG), because that is what the frame data of most such captures show (35 of the 38 measurable Flip = Vert files checked). This is an inference, and some ASIAIR captures differ. It is always reported with the warning “Bayer pattern inferred from Flip=Vert (BGGR); some ASIAIR captures are RGGB – if red and blue look swapped, choose RGGB under Bayer pattern” (with the patterns actually involved). If red and blue look swapped, choose the other pattern yourself. An explicit choice carries no such warning.
  • Other Flip values. Only None and Vert have been checked against frame data. For any other Flip value Auto uses the sidecar's pattern as it stands and warns that this Flip value is unmeasured; if the colours look wrong, choose the pattern yourself. The image itself is never flipped.
  • None (mono) shows the raw CFA frame as one channel.
  • RGGB, GRBG, GBRG, BGGR use that pattern and override the sidecar.

The info block shows where the pattern came from. The image's BAYERPAT keyword and HISTORY note record the pattern used. The sidecar is read as plain text and is never required.

Remembering a chosen pattern

An AVI with no sidecar opens as the raw CFA in mono. To find its pattern, try RGGB, GRBG, GBRG and BGGR under Bayer pattern with Debayer checked and look at the preview. Once the colours look right, click Save pattern... (it stays disabled while Debayer is off, because the raw CFA preview shows no colour to judge by). SERViewer asks “Write <name>.avi.txt with Bayer = RGGB? SERViewer will use it for this file from now on.” (with your file and pattern). Yes writes a small text file next to the video:

[SERViewer]
Bayer = RG
Written By = SERViewer <version> (Bayer pattern chosen by the user)

Then the AVI is opened again with Auto on the same frame, so the new sidecar is read back. The info block shows “Bayer: RGGB (sidecar written by SERViewer)”, and from then on Auto uses this pattern whenever the file is opened. The file names no camera, so the image gets no INSTRUME keyword from it, and it has no Flip line, so the pattern is used as it stands.

  • The button is shown only when nothing is at the sidecar path, so SERViewer never replaces a sidecar, including an ASIAIR sidecar. If a file of that name appears before the write, the write is refused (on a filesystem without hard links, a file created in the same instant as the write could still be replaced). Something at that path that is not a file (for example a folder) is ignored with a warning, and the button stays hidden. To change a saved pattern, delete or edit the .avi.txt file.
  • The file is written to a temporary .partial file first and then moved into place. If the write fails (for example, the folder is read-only), the reason is shown in the info block, the Process Console and a message box. The partial file is removed, and the video stays open.
  • SERViewer does not work out the pattern from the frames. That was tried on real captures and was not reliable: empty frames gave confident answers, and captures from the same week gave contradictory ones.

Save as SER

Save as SER... opens a save dialog (default name: the AVI's name with .ser, in the AVI's folder) and writes the whole video as an 8-bit SER file. The viewer stays on the AVI. A progress dialog shows how far it has got, and its Cancel button stops the conversion.

  • The SER's colour layout is the effective Bayer pattern (mono for None). Its Instrument field is the sidecar's camera. Observer and Telescope are empty.
  • Frames are copied in order, as the viewer decodes them (top row first).
  • No timestamps. The SER has no per-frame timestamp trailer and no UTC time. The start time from the AVI's file name goes only into the header's local DateTime, because on the two files checked the ASIAIR file name clock was about an hour off the file's own modification time, so it is not presented as UTC.
  • The output is written to a temporary .partial file and renamed when complete; SERViewer removes the partial file if the conversion fails or is cancelled. It cannot overwrite the source file; replacing another existing file asks first. The free space needed is checked before writing starts.

From a script or process icon, set saveSerPath (and bayerPattern if needed) and execute the process. An existing file at that path is an error.

Supported SER files

Colour layouts MONO, BAYER_RGGB, BAYER_GRBG, BAYER_GBRG, BAYER_BGGR, RGB and BGR, at 1 to 16 bits per sample. CMY Bayer files (colour IDs 16–19) are refused with an error saying so. Files of any size are read one frame at a time; the whole video is never loaded into memory.

Damaged files are never silently patched up. When the reader recovers (a frame count of 0 or larger than the file holds, as left by a capture that crashed; a byte-order flag that contradicts the data; samples above the declared bit depth), it opens the frames it can prove are complete, and says what it did in the interface's info block, the Process Console and the image's HISTORY keywords. A file it cannot read stops the process with an error message giving the reason.

Files, network and privacy

SERViewer reads only the video file you choose and, for an AVI, its .txt sidecar. It writes only the SER path you choose and, if you click Save pattern..., the .txt sidecar next to the video (each through a temporary .partial file beside it). Opening a frame creates a new, unsaved image window. It uses no network connection and runs no external programs.
