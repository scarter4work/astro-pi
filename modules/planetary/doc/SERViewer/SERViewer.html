SERViewer

Module Planetary. Process > Planetary > SERViewer. This document is installed with the module (doc/tools/SERViewer/).

SERViewer opens SER video files, the format planetary (lucky-imaging) capture programs such as FireCapture and SharpCap write. Executing the process globally opens one frame of the video as an ordinary PixInsight image window, so every PixInsight tool can be used on it.

The interface

  • Open SER... chooses a .ser file. Its first frame is drawn in the preview.
  • Debayer: for Bayer files, show and open frames as RGB (checked) or as the raw CFA mosaic (unchecked). This is the debayer parameter.
  • The preview shows the selected frame scaled to fit, keeping its proportions, on a black background. Its brightness is stretched linearly from 0 to the frame's brightest sample, so a dim planet still fills the display range; an all-zero frame shows black. The stretch is for viewing only: the image that Apply Global opens holds the unstretched samples.
  • Frame: the slider and the number box select the frame (0 to the frame count minus one). They are disabled until a file is loaded.
  • The info block lists the file name, width × height, frame count, colour layout, bit depth (followed by the depth the samples are normalised to, when that differs), the byte order used for 16-bit samples, the UTC time of the first frame (from the timestamp trailer, or none), the header's UTC start time, and any warnings from the reader, plus a warning for the frame shown when its samples exceed the normalisation range. If a file cannot be read, the preview is cleared and the reason is shown here (and in a message box when you chose the file).
  • Apply Global (the round button) opens the selected frame as an image window.

Dragging the interface's instance triangle onto the workspace saves a process icon with the file, frame and debayer setting; opening that icon restores them. The file stays open only while the interface shows it.

Parameters

ParameterTypeDefaultMeaning
filePathString(empty)Absolute path of the .ser file. The process cannot run while it is empty.
frameIndexInt320Frame to open, counting from 0.
debayerBooleantrueBayer (colour-sensor) files only: open as debayered RGB (bilinear interpolation) when true, or as the raw one-channel CFA mosaic when false.

The image it opens

  • 32-bit floating point. Samples are divided by 2depth − 1, so the camera's full range maps to [0,1]. A file whose first frame holds values above its declared bit depth (the header understates it) is normalised by the full range of its sample size instead, 28 − 1 or 216 − 1, so the values stay within [0,1]; a warning says so. If a later frame of a file normalised by its declared depth still exceeds it, that frame opens with values above 1.0 and a warning (Process Console, HISTORY, info block) names the frame.
  • Identifier: the file name with every character other than letters, digits and underscores replaced by an underscore (an underscore is put in front if it starts with a digit), followed by _f and the frame number, for example Saturn_f0. PixInsight adds a suffix if that identifier is already in use.
  • FITS keywords:
    • DATE-OBS: the frame's own UTC timestamp when the file has a timestamp trailer, otherwise the file's UTC start time; left out when neither is valid.
    • INSTRUME, TELESCOP, OBSERVER: the camera, telescope and observer text from the file header, left out when empty.
    • BAYERPAT (RGGB, GRBG, GBRG or BGGR): when a Bayer file is opened with debayer false.
    • HISTORY: the source file name and frame number, plus one SERViewer warning: line for each problem the reader recovered from and for a frame whose samples exceed the normalisation range. Text longer than one FITS card (72 characters) continues on the next HISTORY card.
    Keyword text is plain ASCII: any other character from the file header or the file name is shown as ?.

Supported files

Colour layouts MONO, BAYER_RGGB, BAYER_GRBG, BAYER_GBRG, BAYER_BGGR, RGB and BGR, at 1 to 16 bits per sample. CMY Bayer files (colour IDs 16–19) are refused with an error saying so. Files of any size are read one frame at a time; the whole video is never loaded into memory.

Damaged files are never silently patched up. When the reader recovers (a frame count of 0 or larger than the file holds, as left by a capture that crashed; a byte-order flag that contradicts the data; samples above the declared bit depth), it opens the frames it can prove are complete, and says what it did in the interface's info block, the Process Console and the image's HISTORY keywords. A file it cannot read stops the process with an error message giving the reason.

Files, network and privacy

SERViewer reads only the .ser file you choose. It uses no network connection, runs no external programs, and writes nothing to disk: the frame is opened as a new, unsaved image window.
