What NukeX does

NukeX (Process → NukeX) stacks the FITS light frames you add to it, with optional flats. Instead of averaging or sigma-clipping, it fits a statistical distribution to every pixel's samples across the stack and estimates the signal from the fitted model; it then applies one of its stretches (Auto is recommended). It reads FILTER, BAYERPAT and INSTRUME from the FITS headers and uses a camera quantum-efficiency (QE) database, built into the module, to route each frame and to decompose dual-narrowband colour data into emission lines.

Results open as ordinary PixInsight image windows (NukeX_stacked, NukeX_composed, NukeX_stretched, NukeX_noise). NukeX does not save images to disk; you save them through PixInsight as usual.

Network connections

NukeX makes exactly one kind of network connection: the camera-database update check. Nothing else in the module uses the network. Reading your frames is local only (the FITS library inside NukeX is built without network support, and NukeX opens only the files you select).

What is contacted

HTTPS requests to GitHub, at

https://raw.githubusercontent.com/scarter4work/astro-pi/main/repository/

  • A check downloads two small files: qe_manifest.json and its signature qe_manifest.json.sig.
  • An installation, only after you agree to it, downloads qe_database.json and its signature qe_database.json.sig.

When

  • Automatically, the first time you open the NukeX window in a PixInsight session, but no more often than once every 7 days. Nothing is contacted when PixInsight starts or when the module loads.
  • Whenever you press Check now in the NukeX window (this works even when automatic checking is off).

Your consent

When a newer, verified database exists, NukeX shows what it contains and asks “Install it now?”. Nothing is downloaded beyond the manifest, and nothing is installed, unless you answer Yes. If you answer No, automatic checks do not ask again about that version.

What is sent

Plain HTTPS GET requests for the files above. NukeX sends no identifier, no usage data, no image data and no information about your computer. As with any web request, GitHub receives your IP address and standard request headers.

Security

  • TLS is mandatory, with certificate and host-name verification; plain HTTP is refused. Each response is limited to 8 MiB, and the connection timeout is 20 seconds.
  • The manifest and the database are each signed with Ed25519. NukeX verifies both signatures against a public key compiled into the module, and verifies the database against the SHA-512 digest named in the signed manifest. It refuses an older database than the one it has, and one whose format is newer than it understands.
  • Nothing is written unless every check passes; the new file then replaces the old one in a single step. A rejected update leaves the database in use unchanged and is reported in the Process Console.
  • Being offline is not an error: an automatic check that cannot reach the server stays silent.

Turning it off

Untick Check for camera database updates in the NukeX window. Automatic checks then stop; only Check now contacts the server. To return to the database built into the module, delete ~/.config/nukex4/qe_database.json.

Files written outside the PixInsight installation

1. User data: ~/.config/nukex4/

Created with owner-only permissions (0700). If the HOME environment variable is not set, NukeX uses /tmp/nukex4/ instead. XDG_CONFIG_HOME is not used for this directory.

FileContentsWritten when
qe_update_state.json Update-check settings and state: on/off, check interval in days (default 7, 1–365), time and result of the last check, installed and declined database versions. After each check, and when you change the setting, decline or install an update.
qe_database.json A downloaded, verified camera database. Used only while it is newer than the one built into the module. Only after you accept an update.
filter_aliases.json Filter names (FITS FILTER values) you have taught NukeX, mapped to the filters they stand for. Only when you save the unknown-filter dialog.
phase8_user.sqlite
(with -wal and -shm companion files)		 Your stretch ratings. For each rated run: a random run identifier, the time, the stretch and filter class, image statistics, the stretch parameters and your ratings. No file names, paths or FITS header text. When you save a rating. Grows by one row per rating.
phase8_user_model.json Stretch-parameter model trained from your ratings, used by the Auto stretch. After a rating is saved, once there are enough ratings.
phase8_user.sqlite.corrupt.<time> A damaged rating database, set aside. Only if the rating database is found to be corrupt.

Short-lived .tmp and .stage files appear beside these while they are being replaced, and are removed when the write completes. None of this data is transmitted anywhere.

2. Frame cache: ~/.cache/nukex4/cache/

Stacking keeps aligned frame data in the directory named by NukeX's cacheDirectory parameter (there is no control for it in the NukeX window; it can be changed in a process icon's parameters or from a script). NukeX creates the directory if it is missing. The default is $XDG_CACHE_HOME/nukex4/cache, otherwise ~/.cache/nukex4/cache, otherwise (no HOME) /var/tmp.

  • nukex_cache_XXXXXX (random suffix): aligned frame data for the current run. It is large — about 13 GB for 33 frames from a 24-megapixel colour camera — and is deleted when the run ends. If PixInsight crashes or is killed during a run, the file can remain; it is safe to delete while PixInsight is not running.
  • nukex_cube_XXXXXX: only when the working data would not fit in memory. It is removed from the directory as soon as it is created, so it never remains after a run, but it occupies disk space while the run lasts.

3. Progress files in /tmp

  • /tmp/nukex_progress.log: a time-stamped log of the most recent run's phases and progress messages. Started afresh at the beginning of each run.
  • /tmp/nukex_heartbeat.txt: the current phase and elapsed time, rewritten every 10 seconds during a run.

These fixed paths are not deleted by NukeX; they stay until /tmp is cleaned. They contain processing status only.

4. PixInsight settings

One setting, NukeX/Phase8/RatingPopupSuppressed (the “Don't show rating popup after Execute” choice), is stored through PixInsight's own settings interface.

Files NukeX reads

  • The light and flat FITS frames you add, and a QE override file if you choose one.
  • The files in ~/.config/nukex4/ listed above.
  • /proc/meminfo, to size its work to the memory available.
  • The system's OpenCL driver registrations in /etc/OpenCL/vendors/ (see below).

External programs

None. NukeX does not launch any program or process.

For GPU acceleration (Enable GPU acceleration (OpenCL), on by default), the OpenCL loader built into NukeX reads the driver registrations in /etc/OpenCL/vendors/ (the standard OCL_ICD_VENDORS and OCL_ICD_FILENAMES environment variables can redirect this) and loads the OpenCL driver library installed by your GPU vendor into PixInsight. That driver is part of your system, not of NukeX. Without a usable GPU, NukeX computes on the CPU.
