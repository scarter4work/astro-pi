QE Source — where do the decomposition coefficients come from?

For Bayer-NB decomposition (and broadband-RGB calibration), we need to know each photosite's quantum efficiency at the line wavelengths. Three legitimate scientific paths, plus one that's not.

What we need: ~9 numbers per camera, ~6 per broadband filter set
{
  "cameras": {
    "ASI585MC":  { "qe_at_656": [0.83, 0.05, 0.02],   // R G B at Ha
                   "qe_at_672": [0.81, 0.04, 0.02],   // R G B at SII
                   "qe_at_501": [0.05, 0.85, 0.55] }, // R G B at OIII
    "ASI2600MC": { "qe_at_656": [0.79, 0.06, 0.02], ... },
    "ASI294MC":  { "qe_at_656": [0.75, 0.07, 0.03], ... },
    "default":   { "qe_at_656": [0.80, 0.06, 0.03], ... }  // Sony IMX generic
  },
  "filters": {
    "Optolong-LPro":   { "transmission": [400, 0.85, 580, 0.0, 700, 0.85] },
    "Astronomik-CCD-R":{ "passband": [580, 700], "peak_t": 0.96 },
    ...
  }
}
A

Shipped JSON database — manufacturer-published QE curves

Curate a database from public datasheets (ZWO QE plots, Sony IMX/IMX585/IMX571 datasheets, Astrodon/Optolong/Antlia spec sheets). Resolve at runtime by reading INSTRUME and FILTER from FITS. Fall back to a generic-Sony-IMX default if camera unknown.

Initial coverage: ASI cameras (585/2600/294/533/183/678/485 MC), Sony A7s family if they appear, common Optolong/Antlia filters.

Cost: data-curation pass once; recurring small additions as new cameras appear.

Pros: deterministic, reproducible, the only path that gives bit-stable output across runs. Verifiable against datasheets.

B

Self-calibrating from bright stars (per-frame)

Detect bright A0V or G2V stars in each frame, look them up in Gaia/SIMBAD, fit per-channel response from the difference between observed flux and known SED. Use that to derive per-frame QE × filter weights.

Pros: no database needed; auto-handles unknown cameras; per-frame calibration handles atmospheric effects.

Cost: heavy lift — need plate-solving, Gaia/SIMBAD catalog ingestion, SED fitting, per-frame variance handling. Order-of-magnitude bigger feature than A. Marginal benefit for OSC narrowband (atmospheric effects are tiny across 6nm).

C

A primary, with override JSON in user data dir

Ship the database (A). If ~/.nukex4/qe_overrides.json exists, merge it on top — user's own measured QE values take precedence over manufacturer datasheet values when they conflict.

Pros: reproducible default + escape hatch for users who measure their own QE. Honors the no-stub rule (override is fully functional from day one, not a TODO).

Cost: small — one extra file load + merge step.

D

Hand-tuned 0.25-style weights (DO NOT PICK)

Equal weights everywhere — what the original notes proposed. Treats all photosites as having equal QE at every wavelength.

Why this is wrong: it's the path that produced your green M17. It collapses to the existing broken behavior.

Listed only for completeness so you can see why we ruled it out.
