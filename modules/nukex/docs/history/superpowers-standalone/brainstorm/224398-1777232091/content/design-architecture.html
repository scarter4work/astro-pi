The four architectural pillars

1. Filter is a first-class type. Each frame carries its (FilterClass, FilterName, Camera) before debayer. Disambiguation dialog fires only if FITS FILTER is missing or unrecognized. The classifier is small (lookup table + heuristic for fuzzy names like "L-eXtreme" vs "L_eXtreme"), not a learned model.

2. DebayerEngine stays naive. It demosaics RGGB/BGGR/GRBG/GBRG to R/G/B and stops there. Filter-class awareness lives downstream of debayer. This preserves raw broadband for the alignment + saturation-guard + continuum-subtract paths.

3. The voxel grows filter-class-shaped slots. Voxel is the data structure of record (per the existing rule). For an HaO3 frame entering accumulate, raw R/G/B are passed through the per-pixel Q-matrix solve and routed into the voxel's Ha + OIII slots. For LRGBSHO (multiple filter classes in one batch), the cube has the union of all needed slots; each frame fills the slots its filter class produces.

4. ColorComposer is the only place that knows about palettes. It reads the accumulated cube, applies the calibrated emission-line palette for narrowband, natural color for broadband, Lab/LCH composite for mixed (with continuum-subtract as opt-in advanced mode). The composer is where "no greens" is enforced — not by post-hoc SCNR, but by mathematical construction of the output color from line spectra.
