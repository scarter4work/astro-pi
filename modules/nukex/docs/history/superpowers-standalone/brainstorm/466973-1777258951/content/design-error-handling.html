Design — Section 4 of 5: Error Handling

Per the "no silent fallbacks" rule: errors are loud, propagate up, never paper over. Per "no workarounds": failures point at root causes. Per "no stubs": every error path has a real implementation, not a TODO.

A. Configuration / startup errors — refuse to start the batch
QE database file missing or unreadable
   ⤳ ProcessConsole error: "share/qe_database.json missing — module install corrupt.
                            Reinstall NukeX from PI Resources → Updates."
   ⤳ Execute() returns false; no partial output emitted.

QE override JSON (~/.nukex4/qe_overrides.json) malformed
   ⤳ Specific error with line / column / parser message.
   ⤳ "Override file is malformed at line 23: trailing comma. Fix or delete and retry."
   ⤳ Refuses to start (per no-workarounds — silently ignoring would mask real config bugs).

Filter passband (k_continuum) missing for filter F + camera C, AND continuum-subtract opt-in mode
   ⤳ "Continuum subtract requires filter passband data for {filter}; not available in DB.
       Disable continuum-subtract or update the QE database."
   ⤳ Refuses to start opt-in mode. Default Lab/LCH mode unaffected — runs normally.
B. Per-frame errors — skip frame, loud log, continue batch
Frame read failed                              → existing behavior, log "skipped (read failed)"
Frame dimensions ≠ first-frame dimensions      → existing behavior
Frame Bayer pattern ≠ first-frame Bayer        → reject "BAYERPAT mismatch; frame N has BGGR, batch is RGGB"
Frame INSTRUME differs from prior frames       → ALLOWED if both cameras in QE DB  — per-frame Q matrix.
                                                 Log "frame N camera ASI2600MC, prior was ASI585MC — both QE-known"
                                                 If second camera unknown, treat as next case.
Saturation > reject threshold (existing)       → existing behavior, "SKIPPED — blown out, X%"
Alignment failed                               → existing behavior, weight penalty
C. Filter / camera resolution — UI escape hatch (DisambiguationDialog)
Missing FITS FILTER keyword                    ─┐
Unknown FILTER value (no DB match,             ─┤
  no fuzzy hit on alias table)                  │   ⟹ DisambiguationDialog at batch start
Frame INSTRUME unknown                         ─┘      modal, blocks Execute until resolved

Dialog content:
   "These frames have unrecognised filter / camera metadata:
        15 frames, FILTER='ALP-T', INSTRUME='ASI585MC'      (filter unknown)
         8 frames, FILTER='Ha 7nm', INSTRUME='unknown_dev'  (camera unknown)

    Pick a class for each group, OR cancel:
      ALP-T:    [ Broadband-L | Broadband-RGB | Narrowband-Single | Dual-NB-OSC ]
      Ha 7nm:   [ ... same options ... ]
                + camera fallback: [ ASI585MC | ASI2600MC | Generic Sony IMX OSC ]
   [ Confirm  ]   [ Cancel batch ]"

User picks → choice persisted to FILTER alias table for future runs.
User cancels → batch rejected, no output emitted.

NO silent auto-classification. Period.
D. Phase B + composer errors — bound to known math edge cases
Q matrix singular for (camera, filter)         → fail loud at Phase B start
                                                  "Q matrix for (ASI585MC, HaO3) is singular —
                                                   QE values must form a non-degenerate basis.
                                                   Filter QE in DB is suspect. Report bug + check override."

Q-solve produces negative emission values      → clamp to 0, count occurrences
                                                  in low-SNR pixels (read noise)        log "clamped N pixels (X% of total) to ≥0"
                                                  Not an error — physically expected     this is a quality stat, not a fault.
                                                  in low-photon regions

Lab → sRGB out of gamut                        → soft-clip toward gamut boundary,
                                                  preserve hue, log per-pixel count.
                                                  Standard color-science behaviour.

All frames failed alignment                    → existing behavior — empty stacked output

Multi-source OIII merge with zero contributors → impossible (means all frames failed) — covered above
E. Observability — what the user sees in the Process Console
Per-frame log lines (Phase A):
   Frame 12/100: light_HaO3_005.fits
     filter:   HaO3 (DUAL_NB_OSC)
     camera:   ASI585MC (QE: high confidence)
     debayered, aligned: ok (stars=842, inliers=783, rms=0.412 px)
     accumulated → R_HaO3, G_HaO3, B_HaO3

     HaO3 / ASI585MC: high-confidence Q matrix from share/qe_database.json
     S2O3 / ASI585MC: high-confidence Q matrix
   Multi-source OIII merge: 30 HaO3 contributors + 30 S2O3 contributors
   Negative-emission clamp: 142 pixels (0.0006% of total)
