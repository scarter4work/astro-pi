EZ Stretch

Three stretches of a linear colour image in one dialog, with a live preview — script version 1.0.12.

What it does

EZ Stretch turns a linear (unstretched) colour image into a stretched one with one of three algorithms, chosen in the dialog: Lupton RGB, RNC-ColorStretch and PhotometricStretch. While you adjust the parameters, a preview shows the result. Execute creates a new image window with the stretched result; the image you started from is never changed.

The new window is a 32-bit floating-point RGB image named after the source view, with a suffix for the algorithm: <id>_lupton, <id>_rnc or <id>_photo. EZ Stretch does not save it; you save it through PixInsight as usual.

What it needs

  • PixInsight 1.8.0 or later.
  • An open colour image with at least three channels (the first three are used as red, green and blue). Monochrome images are not supported: the preview stays empty and Execute reports “Processing failed” in the Process Console.
  • Linear data, normally straight from integration and colour calibration. On an image that is already stretched the result is far too bright.

Using it

Open an image, then run Script > scarter4work > EZ Stretch. If no image window is open, the script says so and stops.

  • Target: the image to stretch. The active image window is selected when the dialog opens.
  • Algorithm: the stretch. Only the selected algorithm's parameters are shown; each algorithm keeps its own values while you switch between them.
  • Before / Split / After: the preview shows the source, a split view (source on the left of the line, result on the right; the default), or the result. The source is shown linear and multiplied by 10 so that it is visible; that brightening is for display only.
  • Zoom: the − and + buttons or the mouse wheel zoom by a factor of 1.25 per step, up to 800%; Fit fits the image to the preview. Drag with the left mouse button to pan a zoomed preview.
  • Reset restores the defaults of the selected algorithm. Execute creates the stretched image and writes the algorithm, the source and the time taken to the Process Console. Close closes the dialog.

The preview is computed at display size from a nearest-neighbour sample of the image, so fine detail can look different from the full-resolution result. In Lupton RGB's Rescale to Max clipping mode the preview does not show the final rescaling.

Lupton RGB

The colour-preserving arcsinh stretch of Lupton et al. (2004). With intensity I = (R + G + B) / 3 and black point m, every channel is multiplied by the same factor asinh(α·Q·(I − m)) / (Q·(I − m)) after m is subtracted, so the ratios between the channels (the colour) are kept.

Stretch (α)0.1 – 10005Linear amplification before the arcsinh.
Q (softening)−10 – 308Where the response turns from linear to logarithmic. On Execute, a Q closer to 0 than 0.01 is used as 0.01.
Black Point0 – 0.10Background level subtracted from every channel first.
Saturation0.5 – 21Scales each channel's distance from the mean of the three channels after the stretch (1 = unchanged).
Clipping—Preserve ColorValues above 1: Preserve Color divides all three channels of a pixel by its largest value (hue kept); Hard Clip cuts each channel at 1; Rescale to Max rescales the whole result to the range 0–1.

RNC-ColorStretch

A root-power stretch after the method of Roger N. Clark's rnc-color-stretch: each channel is raised to the power 1 / Root Power. This is an implementation of the root-power stretch only; it does not include the colour-recovery step of Clark's method.

ParameterRangeDefaultEffect
Root Power1 – 2006Each channel becomes x1/Root Power.
Two-Pass Stretchon / offoffApplies a second root-power stretch with Root Power 2.
Root Power 21 – 203The second pass's power (only with Two-Pass Stretch).
S-CurveNone, SC1–SC4NoneA fixed tone curve applied to each channel after the stretch: SC1 x + 0.15·sin(πx)·(1 − x) (lifts the mid-tones); SC2 x0.85; SC3 a small sinusoidal contrast change centred on 0.5; SC4 a blend of 30% linear and 70% smoothstep (x²(3 − 2x)), which adds contrast.
Saturation0.5 – 21Scales each channel's distance from the Rec. 709 luminance (0.2126 R + 0.7152 G + 0.0722 B).

The result is clipped to the range 0–1.

PhotometricStretch

A luminance-weighted arcsinh stretch. After the black point is subtracted, the luminance L = 0.2126 R + 0.7152 G + 0.0722 B (fixed Rec. 709 weights; no camera or sensor data are used) is stretched to asinh(α·L / Q) / asinh(α / Q), and all three channels are multiplied by the same factor, so the colour ratios are kept. The result is clipped to the range 0–1. This algorithm computes every pixel in the script itself, so on a large image Execute can take noticeably longer than the other two.

Stretch (α)0.1 – 1000100Linear amplification before the arcsinh.

Network connections

None. EZ Stretch makes no network connection of any kind.

External programs

None. EZ Stretch does not launch any program or process. Apart from its own code it uses only PixInsight's scripting runtime and, for Lupton RGB, PixInsight's PixelMath process.

Files

EZ Stretch writes no files, inside or outside the PixInsight installation, stores no settings, and opens no files: it reads only the pixels of the image you select. Its only outputs are the new image window and a few lines in the Process Console.

What installing this version removes

EZ Donut Repair is no longer distributed. When the PixInsight update system installs this version of EZ Stretch, it first deletes these two files of EZ Donut Repair from the PixInsight installation, if they are there:

  • src/scripts/scarter4work/EZDonutRepair.js
  • src/scripts/scarter4work/EZDonutRepair.xsgn

Nothing else is removed. If EZ Donut Repair was never installed, nothing happens; the updater's log may mention the two missing files.
